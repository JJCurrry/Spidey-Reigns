## post-commit 钩子又踩一坑（同日）

还原后的第一版把 bundle 生成**后台化**（`&`）并给了 `timeout 60`。实测两个问题：

1. `timeout 60` 太紧——relocated gitdir 上 `git bundle create --all` 要 40–90 秒，被中途掐断，
   留下 `_git_backup_tmp.bundle.lock` 和半截 bundle（`.lock` 没进 .gitignore，还污染了 `git status`）。
2. **后台化更致命**：提交进程结束时子 shell 被一并回收，bundle 生成完了但 `mv` 没跑，
   桌面备份反而不更新（生成时间 14:13，桌面文件还停在 13:43）。

改法（`.husky/post-commit`）：**同步执行** + `timeout 180` + 收尾统一 `rm -f "$TMP" "$TMP.lock"`；
`.gitignore` 补 `.lock`。已手工跑 `sh .husky/post-commit` 验证：桌面 bundle 刷新、无残留。
代价：沙箱内每笔 commit 多约 3–4 分钟（本机环境快得多）。

## 环境坑（重要修订）

**08-31 记的「git 写入全局挂死」是误判。** 本会话 `git add` / `git bundle create`（64MB，90s 内完成）/
`git commit` 全部成功。真因是 pre-commit 的 **lint-staged 单次耗时 2 分 14 秒**（`git stash` 备份+恢复，
relocated gitdir + 64MB 仓库），一笔 commit 实测 3–7 分钟，超过常用超时才被误判为挂死。
**修法：提交放后台任务、超时给 ≥500s，不要用 `--no-verify` 绕。**

**`npx <cmd>` 在沙箱里解析极慢**（`npx prettier` 90s 被 SIGTERM 杀掉），
直接 `node node_modules/prettier/bin/prettier.cjs`（或 `vite-node/vite-node.mjs`）秒回。
判定「命令挂死」前先换掉 npx。
