# T-009 · 部署发布配置（M4-C）

> 里程碑：M4-C ｜ 类型：发布配置 / 不变量无关 ｜ 状态：待实施
> 前序：M4-B 体验打磨（T-008）已完成并提交；M4-A 内容扩充（T-007）已完成。
> 平台裁决（2026-09-03）：用户选 **GitHub Pages**。

## 目标

让作品可一键公开访问：把 `npm run build` 的产物部署到 GitHub Pages
（`https://jjcurrry.github.io/Spidey-Reigns/`），push 到 `main` 即自动构建并发布。
**纯发布配置改动，不触碰任何玩法数值、卡牌内容、core 逻辑**（严守不变量 #4/#7 与原则 7）。
实际 push（L3）与「在仓库 Settings 开启 Pages 源」仍由人执行（ADR-0007）。

## 范围

1. **资源 URL 感知 base（运行时正确性前提）**
   - `src/content/assets.ts` 新增 `assetUrl(path)`：拼接 `import.meta.env.BASE_URL`。
     现 `ASSETS` 路径是写死绝对路径 `/assets/...`，在 GitHub Pages 子路径
     `/Spidey-Reigns/` 下若不感知 base 会 404。
   - `src/ui/AssetFrame.tsx` 的 `<img src>` 改用 `assetUrl(asset.path)`。
   - 新增 `src/content/assets.test.ts`：验证 base 为 `/` 时路径不变、base 为
     `/Spidey-Reigns/` 时正确拼接。本地 dev / Vercel 根域名 / Pages 子路径三场景通用。
2. **Vite base 配置**
   - `vite.config.ts` 加 `base`：`production` 构建为 `/Spidey-Reigns/`，`development`（dev/preview 本地）
     保持 `/`，让本地 `npm run dev` 不受影响、只在生产产物上挂子路径。
3. **GitHub Pages 部署工作流**
   - 新增 `.github/workflows/deploy.yml`：push `main` 触发，`npm ci` → verify（typecheck+lint+test）
     → `npm run build` → `actions/configure-pages` → `upload-pages-artifact`（`dist`）
     → `deploy-pages`。含 `permissions`（pages: write / id-token: write）与 `concurrency`。
4. **包元数据纠正**
   - `package.json` 描述仍写「不公开发布 / 见 ADR-0006」，与 ADR-0007（已裁决公开发布）冲突，
     改为「公开仓库，见 ADR-0007」。

## 不做（范围外）

- 不改 `src/core/`、`src/content/`（卡牌/死法/解锁）任何逻辑与数值。
- 不引入第三方部署/托管依赖（用 GitHub 官方 Actions）。
- 不做 Vercel / Netlify 配置（本次只做 GitHub Pages；资源 base 感知已为双平台留好通用基础）。
- 不自动 `git push`（L3，仅人执行）。

## 验收（可验收，机器优先）

- `npm run verify` 全绿（类型 + lint + 测试；含新增 assetUrl 测试与既有 AssetFrame 断言）。
- **资源 URL 正确**：`assetUrl('/assets/character/x.png')` 在 `BASE_URL='/'` 时返回
  `/assets/character/x.png`；在 `BASE_URL='/Spidey-Reigns/'` 时返回
  `/Spidey-Reigns/assets/character/x.png`（新测试守卫）。
- **构建产物带子路径**：`CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run build` 成功，且
  `dist/index.html` 入口脚本前缀为 `/Spidey-Reigns/assets/`、`dist/assets/` 下图片可经
  `/Spidey-Reigns/assets/...` 访问（资源解析已感知 base）。
- **本地 dev 不变**：`base` 在 development 下为 `/`，`npm run dev` 仍照常根路径访问，无需改访问地址。
- **CI 门禁**：`deploy.yml` 在部署前跑 typecheck+lint+test+build，任一红则不上线。
- **零素材红线**：未新增任何受限素材；资源仍是 `public/assets/` 下的既有原创图。

## 平衡 / 内容影响

无。本里程碑只动发布配置与资源 URL 拼接，不改卡牌/数值；`scripts/balance-audit.ts` 分布应完全不变。

## 人工后续步骤（L3 / 仓库设置，非本 AI 代做）

1. 你本机 `git push -u origin main`（把含 M4-C 的提交推上去；ADR-0007，L3 仅人执行）。
2. 仓库 **Settings → Pages → Source 选「GitHub Actions」**（首次需手动开启；此后 push 自动部署）。
3. 访问 `https://jjcurrry.github.io/Spidey-Reigns/` 验证。

## 实测记录（实施完成，2026-09-03）

- **`npm run verify` 全绿**：14 测试文件 / **82 测试**通过（原 79 + 新增 3 个 `assetUrl` base 拼接守卫）。
  其中 `src/content/assets.test.ts` 验证：base `/` 时路径不变、base `/Spidey-Reigns/` 时正确拼接、
  无结尾斜杠的 base 也能拼接；`src/ui/AssetFrame.test.tsx` 既有「已登记资源渲染真图」断言仍过
  （vitest 下 `BASE_URL` 默认 `/`，`src` 仍为 `/assets/character/aunt-may.png`）。
- **构建产物带子路径**：`CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run build` 成功；
  `dist/index.html` 入口脚本为 `src="/Spidey-Reigns/assets/index-DLl5NZyt.js"`，
  `public/assets/` 图片复制到 `dist/assets/character|icon|ending/`，经 `/Spidey-Reigns/assets/...` 可访问
  （与 `assetUrl` 拼接出的 URL 完全对应，资源不会 404）。
- **本地 dev 不变**：`vite.config.ts` 用 `defineConfig(({ mode }) => ...)` 的 `mode` 区分，
  仅 `mode==='production'`（即 `vite build`）挂 `/Spidey-Reigns/`，`npm run dev` 仍根路径访问。
  （踩坑：曾试 `import.meta.env.PROD`，但 vitest 加载 vite 配置时 `import.meta.env` 尚未注入会报
  `Cannot read properties of undefined (reading 'PROD')`，故改用 `mode` 参数，零类型依赖、零 node 全局依赖。）
- **部署工作流就位**：`.github/workflows/deploy.yml` 用 GitHub Actions 原生 Pages 部署
  （`configure-pages` → `upload-pages-artifact(dist)` → `deploy-pages`），部署前跑
  typecheck+lint+test+build 门禁，任一红不上线；含 `pages: write / id-token: write` 权限与 `concurrency`。
- **包元数据纠正**：`package.json` 描述由「不公开发布 / 见 ADR-0006」改为「公开仓库 / 见 ADR-0007」，与现行发布策略对齐。
- **零素材红线**：未新增任何受限素材；资源仍是 `public/assets/` 下既有 AI 原创图。
- **内容/平衡无影响**：改动只涉及发布配置与资源 URL 拼接，卡牌/数值未动；`balance-audit.ts` 分布理应完全不变（本里程碑不涉及数值，未重跑）。
- **人工后续**：① 你本机 `git push -u origin main`（ADR-0007 L3 仅人执行）；② 仓库
  Settings → Pages → Source 选「GitHub Actions」首次手动开启；③ 访问
  `https://jjcurrry.github.io/Spidey-Reigns/` 验证。
