## 踩坑与已试过且失败的方法

- ❌ `no-restricted-globals` 直接限制 `Math` —— 失败原因：会连带禁掉 `Math.floor` / `Math.imul`
  （rng 自己就要用）。改用 `no-restricted-properties` 精确限制 `Math.random` 与 `Date.now`。
- ❌ Vitest 全局 `environment: 'node'` + 无差别 `setupFiles` 引入 jest-dom ——
  失败原因：node 环境无 `document`。改为默认 jsdom、`src/core/**` 用 `environmentMatchGlobs` 强制 node，
  setup 文件用 `typeof document !== 'undefined'` 守卫。这样反而把不变量 #7 变成了可执行检查。
- ❌ `.husky/pre-commit` 只写一行 `npx lint-staged` ——
  失败原因：**Git 钩子不继承交互式 shell 的 PATH**，node/npx 在终端里可用、在钩子里却报
  `npx: command not found`（exit 127）。修法见 `.husky/pre-commit`：补 PATH 候选目录，再直接
  `node node_modules/lint-staged/bin/lint-staged.js`（绕开 npx 的联网解析，更快且可离线）。
- ❌ 首次 `npm install` 后有 3 个包（`agent-base`、`http-proxy-agent`、`@humanfs/*`）的
  `dist/*.js` 缺失 —— 失败原因：安装过程的清理环节误删（沙箱环境的可疑行为，重装后又复现了一次）。
  修法：`rm -rf node_modules/<包名>` 后重装。排障脚本留在 `scripts/check-deps.mjs`
  （`npm run deps:check`）；注意它只读 `main` 字段，对 `exports` 优先的 ESM 包会误报。
- ❌ 用 `as const satisfies readonly Card[]` 后，测试里直接访问 `card.fallback` 报
  「属性不存在」——失败原因：字面量元组里没写 `fallback` 的卡，该属性在类型上根本不存在。
  修法：测试入口显式向上转型 `const cards: readonly Card[] = CARDS;`。
