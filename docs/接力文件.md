## 踩坑与已试过且失败的方法

- ❌ `no-restricted-globals` 直接限制 `Math` —— 失败原因：会连带禁掉 `Math.floor` / `Math.imul`。
  改用 `no-restricted-properties` 精确限制 `Math.random` 与 `Date.now`。
- ❌ Vitest 全局 `environment: 'node'` + 无差别 `setupFiles` 引入 jest-dom —— 改为默认 jsdom +
  `environmentMatchGlobs` 让 `src/core/**` 强制 node，setup 用 `typeof document !== 'undefined'` 守卫。
- ❌ `.husky/pre-commit` 只写一行 `npx lint-staged` —— Git 钩子不继承交互式 shell 的 PATH。
  修法：补 PATH 候选目录，再直接 `node node_modules/lint-staged/bin/lint-staged.js`。
- ❌ 首次 `npm install` 后部分包 `dist/*.js` 缺失 —— 沙箱清理行为，修法 `rm -rf node_modules/<包>` 后重装。
- ❌ `as const satisfies readonly Card[]` 后测试直接访问 `card.fallback` 报「属性不存在」——
  修法：测试入口显式 `const cards: readonly Card[] = CARDS;`。
- ⚠️ **M1 提交时 `.git` 目录凭空消失**：一次 `git commit` 被 husky pre-commit 钩子以
  `3dc24b71... is not a valid object` 中止后，整个 `.git` 目录不见了（疑似沙箱对仓库元数据的清理）。
  **恢复步骤（已验证可行）**：`git init` → `git remote add origin <url>` → `git fetch origin`（只写进 FETCH_HEAD，
  远端跟踪引用 `refs/remotes/origin/main` 未落盘，故要用 FETCH_HEAD 里的 SHA）→
  `git reset --mixed <M0_SHA>`（重置索引/HEAD 到 M0，不动工作树，M1 改动全保留）→
  `git branch -M main` → 按里程碑 a–f 分批提交。教训：**关键节点先 `git bundle create` 打离线备份到工作区外**，
  比依赖本地 `.git` 更稳；本会话已生成 `Spidey-Regins-M1-backup.bundle` 放桌面。
- ⚠️ `git bundle create <绝对Windows路径>` 报「Unable to create .lock: No such file or directory」——
  git 对 `/c/Users/...` 绝对路径有怪癖。修法：先在仓库内 `git bundle create <名>.bundle main`，再 `mv` 到目标目录。
