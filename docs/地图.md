## 架构概览

三层单向依赖，**箭头只能从上往下**：

```
src/content/   数据层：卡牌、结局、常量（纯数据，无逻辑）
      │
      ▼
src/core/      玩法层：抽卡、数值结算、死亡判定（纯函数，零 UI / 零浏览器依赖）
      │
      ▼
src/ui/        表现层：React 组件、滑动手势、动画、资源加载
```

数据流：`Content --(注入)--> Core --(只读状态)--> UI --(玩家选择)--> Core`

关键约束：**依赖绝不反向**。`core` 不知道 `ui` 存在，`content` 不知道 `core` 存在。
存档与随机种子都在最外层注入，不埋在模块内部。存档逻辑集中在 `src/save/`（`migrate.ts` 纯函数迁移 + `storage.ts` IO 隔离），由 `src/App.tsx` 在顶层调用，`core`/`ui` 不直接碰 localStorage。

一局的最小闭环：
`createReign(seed)` → `drawCard(cards, state, rng)` → 玩家选左/右 → `applyChoice(...)`
→ `evaluateDeath(...)` → 有死亡则结束，否则回到 `drawCard`。

## 模块索引（路径 → 职责 → 关键入口）

| 模块 | 路径 | 职责 | 关键入口 / 禁忌 |
|---|---|---|---|
| 类型契约 | `src/core/types.ts` | 四指标 / 卡 / 选项 / 效果 / 条件 / 结局的全部类型定义 | 入口：文件顶部 `STAT_KEYS`；禁忌：改这里等于改全仓，需走 ADR |
| 随机源 | `src/core/rng.ts` | 可注入、可重现的伪随机（mulberry32） | 入口：`createRng(seed)`；禁忌：任何地方裸调 `Math.random()`（不变量 #1） |
| 数值 | `src/core/stats.ts` | 指标钳制、效果结算、越界检测 | 入口：`applyEffect` / `findBreach`；禁忌：绕过 `clampStat` 直接写指标 |
| 抽卡 | `src/core/deck.ts` | 条件过滤 + 权重抽取 + `once` 去重 + 兜底回退 | 入口：`drawCard`；**黄金路径，照此新增** |
| 局循环 | `src/core/game.ts` | 创建牌局、应用选择、判定死亡 | 入口：`createReign` / `applyChoice` / `evaluateDeath` |
| 卡牌内容 | `src/content/cards.ts` | 全部事件卡的文案与数值 | 只放数据；禁止出现函数与控制流（不变量 #4） |
| 结局内容 | `src/content/deaths.ts` | 全部死亡结局文案 | 同上 |
| 常量 | `src/content/constants.ts` | `SAVE_VERSION`、初始指标、边界值 | 入口：`INITIAL_STATS`；改 `SAVE_VERSION` 必须同步存档迁移 |
| UI（目录） | `src/ui/` | React 组件、滑动手势、资源加载、占位降级 | 入口：`src/App.tsx`；禁忌：在此写玩法规则 |
| 种子注入 | `src/ui/seed.ts` | 最外层用 `crypto.getRandomValues` 生成种子（不变量 #1） | 入口：`makeSeed` |
| 接线 Hook | `src/ui/useReign.ts` | 把 Core 状态接到 React；无 useEffect 重复抽卡；`cards`/`deaths` 可选 + ref 持有最新值 | 入口：`useReign` |
| 指标条 | `src/ui/StatBars.tsx` | 四指标趋势条，靠近边界变色，**不显示数值**（ASSUMPTION-NO-NUMBER） | 入口组件 |
| 卡面视图 | `src/ui/CardView.tsx` | 事件卡文案与说话者头像（头像走 AssetFrame 占位） | 入口组件 |
| 滑动手势 | `src/ui/SwipeArea.tsx` | 指针拖拽 + 键盘 ←/→ 滑动，阈值 80、倾斜回弹 | 入口组件 |
| 结局页 | `src/ui/EndingScreen.tsx` | 死亡结局展示 + 再来一局 | 入口组件 |
| 编排层 | `src/ui/ReignGame.tsx` | 组合上述 UI，`death` 触发 `onDeath` 回调 | 入口组件 |
| 资源占位 | `src/ui/AssetFrame.tsx` | 资源缺失时程序化降级（ADR-0005 占位层），不白屏不抛错 | 入口组件 |
| 资源清单 | `src/content/assets.ts` | 资源清单协议（ADR-0005），`ASSETS` 当前为空 | 入口：`getAsset` |
| 解锁档位 | `src/content/unlocks.ts` | 按已死局数分 4 档解锁卡组 | 入口：`availableCards` / `unlockedCardIds` |
| 存档迁移 | `src/save/migrate.ts` | `SaveData` 纯函数迁移（不变量 #2，版本缺失/损坏安全降级） | 入口：`migrateSave` / `recordDeath` |
| 存档 IO | `src/save/storage.ts` | localStorage 读写 + 异常兜底降级 | 入口：`loadSave` / `recordAndPersist` |

## 黄金路径 / 参考实现（照着它新增，质量最高）

- **`src/core/deck.ts`** —— 全仓 `core` 层代码的样板：纯函数、依赖（`Rng`）全部由入参注入、
  边界情况（空候选池、`once` 去重）显式处理而不是抛错、每个分支都有对应用例。
  新增任何 `core` 模块前先读它。
- **`src/core/__tests__/deck.test.ts`** —— 新增 `core` 函数时，测试照这个结构写（正常路径 / 边界 / 随机可重现）。
