## 架构概览

三层单向依赖，**箭头只能从上往下**：

```
src/content/   数据层：卡牌、结局、常量（纯数据，无逻辑）
      │
      ▼
src/core/      玩法层：抽卡、数值结算、死亡判定（纯函数，零 UI / 零浏览器依赖）
      │
      ▼
src/ui/        表现层：React 组件、滑动手势、动画、资源加载
```

数据流：`Content --(注入)--> Core --(只读状态)--> UI --(玩家选择)--> Core`

关键约束：**依赖绝不反向**。`core` 不知道 `ui` 存在，`content` 不知道 `core` 存在。
存档与随机种子都在最外层注入，不埋在模块内部。

一局的最小闭环：
`createReign(seed)` → `drawCard(cards, state, rng)` → 玩家选左/右 → `applyChoice(...)`
→ `evaluateDeath(...)` → 有死亡则结束，否则回到 `drawCard`。

## 模块索引（路径 → 职责 → 关键入口）

| 模块 | 路径 | 职责 | 关键入口 / 禁忌 |
|---|---|---|---|
| 类型契约 | `src/core/types.ts` | 四指标 / 卡 / 选项 / 效果 / 条件 / 结局的全部类型定义 | 入口：文件顶部 `STAT_KEYS`；禁忌：改这里等于改全仓，需走 ADR |
| 随机源 | `src/core/rng.ts` | 可注入、可重现的伪随机（mulberry32） | 入口：`createRng(seed)`；禁忌：任何地方裸调 `Math.random()`（不变量 #1） |
| 数值 | `src/core/stats.ts` | 指标钳制、效果结算、越界检测 | 入口：`applyEffect` / `findBreach`；禁忌：绕过 `clampStat` 直接写指标 |
| 抽卡 | `src/core/deck.ts` | 条件过滤 + 权重抽取 + `once` 去重 + 兜底回退 | 入口：`drawCard`；**黄金路径，照此新增** |
| 局循环 | `src/core/game.ts` | 创建牌局、应用选择、判定死亡 | 入口：`createReign` / `applyChoice` / `evaluateDeath` |
| 卡牌内容 | `src/content/cards.ts` | 全部事件卡的文案与数值 | 只放数据；禁止出现函数与控制流（不变量 #4） |
| 结局内容 | `src/content/deaths.ts` | 全部死亡结局文案 | 同上 |
| 常量 | `src/content/constants.ts` | `SAVE_VERSION`、初始指标、边界值 | 入口：`INITIAL_STATS`；改 `SAVE_VERSION` 必须同步存档迁移 |
| UI（M1 起） | `src/ui/` | React 组件、滑动手势、资源加载 | 入口：`src/App.tsx`；禁忌：在此写玩法规则 |

## 黄金路径 / 参考实现（照着它新增，质量最高）

- **`src/core/deck.ts`** —— 全仓 `core` 层代码的样板：纯函数、依赖（`Rng`）全部由入参注入、
  边界情况（空候选池、`once` 去重）显式处理而不是抛错、每个分支都有对应用例。
  新增任何 `core` 模块前先读它。
- **`src/core/__tests__/deck.test.ts`** —— 新增 `core` 函数时，测试照这个结构写（正常路径 / 边界 / 随机可重现）。

## 关键流程入口

- 测试入口：`npm test`（单次）/`npm run test:watch`
- 覆盖率入口：`npm run coverage`（`src/core/**` 棘轮阈值见 `vite.config.ts`，只进不退）
- 验证入口（DoD 怎么证明）：`npm run verify` = 类型 + lint + 测试，一条命令全绿
- 不变量守卫测试：`src/core/__tests__/content.test.ts`（卡牌完整性，对应不变量 #5）
- CI 门禁：`.github/workflows/ci.yml`
