# ADR-0004：随机源与时间源必须注入，禁止裸调

## 背景（Context）

本项目的可玩性高度依赖随机：抽哪张卡、事件何时出现、死法节奏。
如果随机不可控，会同时失去三样东西：① 单元测试无法写（每次结果都不同）；
② 玩家报告的 BUG 无法复现；③ 卡牌平衡无法用模拟脚本量化（"跑 1000 局看平均存活回合"）。

Reigns 类游戏的平衡工作是纯数据活——跑批量模拟、看存活曲线与死法分布。
这些在随机不可重现的前提下全部做不了。

## 决定（Decision）

- 随机一律来自 `src/core/rng.ts` 的 `createRng(seed)`（mulberry32），**由调用方注入**到需要的函数。
- 一局开始时生成一次 `seed`，并存入 `ReignState`；存档时一并持久化。
- 时间源（若未来需要，如现实时间事件）同样必须注入，禁止裸调。
- 用 ESLint `no-restricted-globals` 把 `Math.random` 与 `Date` 列为受限全局，撞上即失败（不变量 #1，L1 已自动化）。

## 被否决的备选及原因（Alternatives considered）

- **直接 `Math.random()`，测试时 monkey-patch 掉**：实现最省事。
  否决原因：全局打补丁脆弱且与测试顺序耦合；一局的可重现性无法从代码结构上保证。
- **引入第三方 seeded random 库（如 seedrandom）**：功能更全。
  否决原因：mulberry32 只要十行、零依赖、分布对本场景足够；少一个依赖就少一处供应链与维护面。
- **用真实时间做种子、不做持久化**：玩家拿到"随机"体验即可。
  否决原因：BUG 复现与平衡模拟的能力是本项目的长期杠杆，不能为了省一个字段放弃。

## 后果（Consequences）

- 正面：同种子 + 同操作序列 = 完全相同的一局；批量平衡模拟可脚本化；BUG 可复现。
- 负面：每个需要随机的函数都要多一个 `rng` 参数，签名略啰嗦；忘记传的写法会被 lint 拦下。
- 后续要注意：新增任何"随机"行为时，先问它是否走注入的 `Rng`——
  看到 `Math.random` 出现在 diff 里就是红灯。
